変数とデータ型

Javaのエラーは、ほとんどの場合「型」「値」「参照」のどれかを取り違えたところから始まります。 この資料では、最初につまずきやすいポイントだけを深掘りし、ゼロから理由を説明できる状態を目指します。

全体像 宣言と初期化 型の約束 整数の割り算 リテラル 参照とnull String比較 var ラッパー型 小数誤差

まず押さえる全体像

変数は「値に名前を付けるもの」です。ただしJavaでは、名前を付けるときに必ず「どんな種類の値を入れるか」を決めます。 この種類が型です。型を先に決めることで、Javaは実行前に多くの間違いを見つけられます。

変数名

人間が値を読みやすくするための名前。例: score, userName

型

値の種類。例: intは整数、Stringは文字列。

値

実際に扱うデータ。例: 80, "Sato", true

Javaの型は、書き方を面倒にするためのものではありません。間違った値を早めに止めるための仕組みです。

01

宣言しただけの変数は使えない

変数を作ることを宣言といいます。宣言は「この名前の変数を使います」とJavaに伝えるだけです。 そこに値を入れることを初期化といいます。Javaのローカル変数は、初期化されるまで使えません。 

int score;              // 宣言だけ
// System.out.println(score);  // エラー: 値が入っていない

score = 80;             // 代入
System.out.println(score);
重要: 「変数がある」ことと「値が入っている」ことは別です。 Javaは、値が入っていない可能性があるローカル変数を使わせません。

なぜつまずくのか

初心者は int score; と書いた時点で、何か初期値が自動で入ると思いがちです。 しかしメソッドの中で作ったローカル変数は、自分で値を入れてからでないと使えません。 これは、意図しない値を使ってバグになるのを防ぐためです。

つまずく書き方

int count;
System.out.println(count);

宣言しただけなので、表示する値がありません。

安全な書き方

int count = 0;
System.out.println(count);

最初の値を決めてから使います。

練習問題 01

次のコードが動くように、必要な修正をしてください。

public class Main {
  public static void main(String[] args) {
    int total;
    total = total + 100;
    System.out.println(total);
  }
}
解答例と説明 解答例 
public class Main {
  public static void main(String[] args) {
    int total = 0;
    total = total + 100;
    System.out.println(total);
  }
}

total = total + 100; の右側で、まだ値が入っていない total を読もうとしているためエラーになります。 先に 0 などの初期値を入れると、0 + 100 を計算できます。

02

型が違う値はそのまま入らない

Javaの変数は、宣言した型に合う値だけを入れられます。 intの変数には整数、booleanの変数にはtrueかfalse、Stringの変数には文字列を入れます。 

int age = 20;
boolean active = true;
String name = "Sato";
重要: 見た目が似ていても、型が違えば別物です。 20は整数、"20"は文字列です。

なぜつまずくのか

人間には 20 と "20" がどちらも「20」に見えます。 しかしJavaにとって、前者は計算できる数値、後者は文字の並びです。 型が違えば、できる操作も変わります。

値 型 できること
20 int 足し算、引き算、比較など
"20" String 文字数を調べる、連結するなど
true boolean 条件分岐に使う

練習問題 02

コンパイルエラーになる行をすべて選び、正しい書き方に直してください。

int price = "1200";
String code = 1200;
boolean paid = false;
boolean deleted = 0;
解答例と説明 解答例 
int price = 1200;
String code = "1200";
boolean paid = false;
boolean deleted = false;

intには整数を入れます。Stringにはダブルクォートで囲んだ文字列を入れます。 booleanにはtrueまたはfalseだけを入れられます。 Javaでは0をfalseとして扱いません。

03

整数同士の割り算は整数になる

int同士で割り算をすると、結果もintになります。 小数部分は丸められるのではなく、切り捨てられます。 

int total = 5;
int count = 2;

System.out.println(total / count); // 2
重要: 5 / 2 は数学では 2.5 ですが、Javaでint / intをすると 2 になります。

小数の結果がほしい場合

片方をdoubleにすると、小数を含む計算になります。 変数そのものをdoubleにするか、計算時にキャストします。 

int total = 5;
int count = 2;

System.out.println((double) total / count); // 2.5

期待とずれる書き方

double average = 5 / 2;
System.out.println(average); // 2.0

先に整数同士で計算され、その後doubleに入ります。

意図が伝わる書き方

double average = 5.0 / 2;
System.out.println(average); // 2.5

片方が小数なので、小数の割り算になります。

練習問題 03

平均点が83.333...になるように修正してください。

int totalScore = 250;
int studentCount = 3;
double average = totalScore / studentCount;

System.out.println(average);
解答例と説明 解答例 
int totalScore = 250;
int studentCount = 3;
double average = (double) totalScore / studentCount;

System.out.println(average);

totalScore / studentCountのままだとint / intです。 (double) totalScoreと書くことで、左側を小数として扱い、結果も小数になります。

04

文字・文字列・数値リテラルを混同する

コードに直接書いた値をリテラルといいます。 Javaでは、書き方によってリテラルの型が決まります。

書き方 意味 例
100 整数 int price = 100;
100L longの整数 long id = 100L;
0.1 doubleの小数 double rate = 0.1;
0.1F floatの小数 float rate = 0.1F;
'A' 1文字 char rank = 'A';
"A" 文字列 String rank = "A";
重要: シングルクォートはchar、ダブルクォートはStringです。 'A'と"A"は同じ見た目でも型が違います。

なぜLやFが必要なのか

整数リテラルは基本的にint、小数リテラルは基本的にdoubleとして扱われます。 そのため、longとして大きな整数を書くときはL、floatとして小数を書くときはFを付けます。 

long userId = 3000000000L;
float taxRate = 0.1F;

練習問題 04

次のコードを、すべてコンパイルできる形に直してください。

char initial = "T";
String label = 'A';
long largeNumber = 3000000000;
float rate = 0.08;
解答例と説明 解答例 
char initial = 'T';
String label = "A";
long largeNumber = 3000000000L;
float rate = 0.08F;

charはシングルクォート、Stringはダブルクォートです。 3000000000はintの範囲を超えるためLを付けます。 0.08はdoubleなので、floatに入れるならFを付けます。

05

参照型とnullで止まる

Javaの型は、大きくプリミティブ型と参照型に分けられます。 プリミティブ型は値そのものを扱います。参照型は、オブジェクトの場所を指す参照を扱います。

分類 例 イメージ
プリミティブ型 int, double, boolean, char 変数の中に値そのものがある
参照型 String, 配列, クラス, Integer 変数の中にオブジェクトへの参照がある

nullは「参照先がない」という意味です。 参照型の変数にはnullが入ることがあります。 その状態でメソッドを呼ぶと、NullPointerExceptionが起きます。 

String name = null;
// System.out.println(name.length()); // NullPointerException
重要: nullは空文字""とは違います。 空文字は「長さ0の文字列」です。nullは「文字列そのものがない」状態です。

止まりやすい書き方

String name = null;
System.out.println(name.length());

参照先がないのに、文字列の機能を呼んでいます。

確認してから使う

String name = null;
if (name != null) {
  System.out.println(name.length());
}

参照先がある場合だけメソッドを呼びます。

練習問題 05

次のコードで例外が起きないように修正してください。nameがない場合は"名前未登録"と表示してください。

String name = null;
System.out.println(name.toUpperCase());
解答例と説明 解答例 
String name = null;

if (name == null) {
  System.out.println("名前未登録");
} else {
  System.out.println(name.toUpperCase());
}

nameがnullのとき、toUpperCase()は呼べません。 先にname == nullで確認し、参照先がない場合の処理を分けます。

06

Stringを==で比べてしまう

Stringは参照型です。 参照型に対して==を使うと、基本的には「同じ内容か」ではなく「同じオブジェクトを指しているか」を比べます。 

String a = new String("Java");
String b = new String("Java");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
重要: 文字列の内容を比べたいときは、原則としてequalsを使います。 ==は「同じ場所を指しているか」を見る、と考えます。

なぜややこしいのか

String x = "Java";のような書き方では、Javaが同じ文字列を共有することがあります。 そのため==でもtrueになるケースがあり、初心者には余計に混乱します。 しかし、それに頼るべきではありません。内容比較はequalsと覚えるのが安全です。 

String input = "yes";

if (input.equals("yes")) {
  System.out.println("続行します");
}

練習問題 06

次の条件分岐を、文字列の内容比較として安全な書き方に直してください。

String answer = new String("yes");

if (answer == "yes") {
  System.out.println("OK");
}
解答例と説明 解答例 
String answer = new String("yes");

if ("yes".equals(answer)) {
  System.out.println("OK");
}

answer == "yes"は参照の比較です。 "yes".equals(answer)なら内容を比較できます。 文字列リテラル側からequalsを呼ぶと、answerがnullでも例外になりにくい書き方になります。

07

varを動的な型だと思ってしまう

varは、Java 10以降で使えるローカル変数の型推論です。 型を書かなくてよいだけで、型がなくなるわけではありません。 

var score = 80;  // int と推論される
// score = "80"; // エラー: Stringは入れられない
重要: varは「あとから何でも入れられる変数」ではありません。 最初の値を見て、コンパイル時に型が決まります。

使ってよい場面と避けたい場面

場面 判断 理由
var name = "Sato"; 使いやすい 右側を見ればStringだと分かる
var result = service.get(); 注意 戻り値の型が読み手に分かりにくい場合がある
var x = null; 使えない nullだけでは型を推論できない

練習問題 07

次のコードの問題点を説明し、正しく直してください。

var value = 100;
value = "100";
解答例と説明 解答例 1 
var value = 100;
value = 200;
解答例 2 
var value = "100";
value = "200";

var value = 100;と書いた時点で、valueはintです。 その後に文字列"100"は入れられません。 数値として扱うなら数値を入れ続け、文字列として扱うなら最初から文字列で初期化します。

08

Integerなどをintと同じ感覚で比べる

intはプリミティブ型ですが、Integerは参照型です。 Integerは数値をオブジェクトとして扱うための型です。 

int a = 1000;
int b = 1000;
System.out.println(a == b); // true

Integer x = 1000;
Integer y = 1000;
System.out.println(x == y);      // false の可能性
System.out.println(x.equals(y)); // true
重要: Integerは参照型です。 値として比べたいならequalsを使うか、必要に応じてintとして扱います。

なぜ存在するのか

コレクションなど、オブジェクトを扱う仕組みではプリミティブ型をそのまま入れられない場面があります。 そのためintに対応するInteger、doubleに対応するDoubleのようなラッパー型があります。 

List<Integer> scores = new ArrayList<>();
scores.add(80);

上のように書けるのは、JavaがintとIntegerの変換を自動で補ってくれるためです。 ただし、比較まで完全に同じ感覚でよいわけではありません。

練習問題 08

次のコードを、数値として等しいかを正しく判定する形に直してください。

Integer expected = 1000;
Integer actual = 1000;

if (expected == actual) {
  System.out.println("一致");
}
解答例と説明 解答例 
Integer expected = 1000;
Integer actual = 1000;

if (expected.equals(actual)) {
  System.out.println("一致");
}

Integerは参照型なので、==では参照先の比較になります。 数値として同じかを見たい場合は、equalsを使います。 ただしexpectedがnullになる可能性がある場合は、先にnull対策も必要です。

09

doubleを正確な小数だと思ってしまう

doubleは小数を扱えますが、すべての10進小数を正確に表せるわけではありません。 コンピュータ内部では2進数で表現するため、0.1や0.2のような値に微小な誤差が出ることがあります。 

System.out.println(0.1 + 0.2); // 0.30000000000000004 など
重要: doubleは測定値や平均などには便利ですが、金額のように正確な10進計算が必要な場面では注意が必要です。

どう考えればよいか

小数を「だいたいの量」として扱うならdoubleで十分なことが多いです。 一方、1円単位の金額や税計算など、丸め方が結果に影響する場合は、要件に応じてBigDecimalを使います。 

import java.math.BigDecimal;

BigDecimal a = new BigDecimal("0.1");
BigDecimal b = new BigDecimal("0.2");
System.out.println(a.add(b)); // 0.3

注意が必要

double price = 0.1;
double tax = 0.2;
System.out.println(price + tax);

2進数で表す都合により、誤差が出ることがあります。

正確さを重視

BigDecimal price = new BigDecimal("0.1");
BigDecimal tax = new BigDecimal("0.2");
System.out.println(price.add(tax));

文字列から作ることで、意図した10進数として扱いやすくなります。

練習問題 09

金額計算として、次のコードの問題点を説明し、BigDecimalを使う形に直してください。

double item = 0.1;
double fee = 0.2;
double total = item + fee;
System.out.println(total);
解答例と説明 解答例 
import java.math.BigDecimal;

BigDecimal item = new BigDecimal("0.1");
BigDecimal fee = new BigDecimal("0.2");
BigDecimal total = item.add(fee);

System.out.println(total);

doubleでは0.1や0.2を正確に表せないため、金額計算では誤差が問題になることがあります。 BigDecimalを使う場合は、new BigDecimal("0.1")のように文字列から作ると意図した10進数を表しやすくなります。
